# JD 定制

## JD 解析结构

内部先把 JD 拆成：

```text
- 核心职责：
- 必要技能：
- 加分项：
- 业务背景：
- 隐藏考察点：
- 关键词：
```

隐藏考察点示例：

| JD 措辞 | 实际考察 |
| --- | --- |
| 业务感强 | 能理解业务，不只是执行技术任务 |
| 对结果负责 | Ownership、闭环能力 |
| 快速学习 | ramp-up 速度、技术广度 |
| 跨团队协作 | 影响力、沟通和推进 |
| 大规模系统 | QPS、数据量、稳定性、容量设计 |
| 创业精神 | 主动性、模糊问题处理、脏活累活 |

## 定制策略

### 内容排序

把最匹配 JD 的内容前置：

1. 摘要中的定位和最强成果
2. 核心技能中的 JD 关键词
3. 最近经历中与 JD 最相关的项目
4. 项目 bullet 中最能证明能力的结果

### 内容裁剪

- 强相关：前置、展开、量化。
- 中相关：保留但压缩。
- 弱相关：删除或放到后面。
- 有风险但无法删除：改写成更职业、可解释的版本。

### 关键词处理

- 可以调整表达和排序，不能为了 ATS 堆砌无证据关键词。
- 技能列表出现的能力，最好能在项目经历里找到证据。
- 同义词可按 JD 表达统一，例如“微服务治理/服务治理”“数据看板/BI 报表”。

## 按岗位调整叙事

技术岗：

- 技术复杂度、架构权衡、性能/稳定性、工程质量、故障复盘。

产品岗：

- 用户问题、需求判断、指标变化、跨团队推进、商业理解。

运营岗：

- 用户分层、增长策略、活动设计、内容/渠道、数据复盘。

数据分析岗：

- 指标体系、SQL/统计、AB 测试、归因分析、业务建议落地。

管理岗：

- 目标拆解、团队协作、机制建设、决策权衡、组织产出。

## JD 不完整时

如果用户只给岗位名，先按通用岗位画像处理，并问 1 到 3 个关键澄清问题，例如：

- 这个岗位更偏业务系统、基础架构、算法工程还是应用开发
- 目标公司/行业是什么
- 你最想突出技术深度、业务结果还是管理协作
