# 结构化面试评分与追问

## 目标

把简历亮点转成可评分、可追问、可防守的面试准备材料。优先使用结构化面试思路：同一能力用一致问题和评分标准评估。

## 能力评分维度

| 维度 | 高分表现 | 低分表现 |
| --- | --- | --- |
| 问题理解 | 能说清背景、目标、约束和影响 | 只说“公司要求做” |
| 个人贡献 | 动作具体，有决策或关键执行 | 全是“我们”，边界不清 |
| 方案判断 | 有备选方案、权衡和风险控制 | 只背概念，不结合项目 |
| 结果证明 | 有指标、范围、用户或证据 | 只有“效果不错” |
| 复盘能力 | 能承认不足并提出改进 | 过度完美，没有反思 |
| 沟通表达 | 结论先行，层次清楚 | 细节堆砌，抓不到重点 |

## 评分等级

| 分数 | 标准 |
| --- | --- |
| 1 | 回答空泛，无法证明真实经历 |
| 2 | 有经历但缺背景、结果或个人贡献 |
| 3 | 能说明基本过程和个人动作 |
| 4 | 有清楚权衡、结果和复盘 |
| 5 | 能体现复杂问题处理、影响范围和方法沉淀 |

## 追问链

每个亮点至少准备 5 层：

1. 为什么要做这个项目？
2. 你个人负责哪部分？
3. 当时有哪些方案，为什么选这个？
4. 结果怎么衡量，有什么证据？
5. 如果重做，你会怎么优化？

## STAR/BEI 检查

用户回答后检查：

- S/T：背景和目标是否清楚。
- A：个人动作是否具体。
- R：结果是否有证据。
- Boundary：团队贡献和个人贡献是否区分。
- Learning：是否有复盘和改进。

## 好答案结构

```text
一句话结论
-> 背景和问题
-> 我的关键动作
-> 为什么这样选
-> 结果和证据
-> 复盘和改进
```

## 输出格式

```markdown
## Q. [面试问题]

- 考察能力：
- 评分标准：
- 好答法：
- 差答法：
- 可能追问：
- 需要补齐的证据：
```
