# 素材收集与提问

## 目标

把用户的真实经历整理成可复用的求职素材库。之后无论是写简历、改简历、生成讲稿还是模拟面试，都从素材库取材，而不是临时编故事。

## 从零创建简历时先收集

优先问最少但最高价值的问题。不要一次性问几十个问题；按模块推进。

### 基础档案

- 目标岗位或方向是什么
- 当前身份：应届、社招、转行、管理岗、自由职业、创业后求职
- 工作年限、城市偏好、行业偏好
- 是否有目标 JD

### 简历骨架

- 教育背景：学校、专业、时间、亮点
- 工作经历：公司、岗位、时间、团队/业务背景
- 项目经历：项目名、角色、目标、技术栈、结果
- 技能：只保留能被经历证明、且对目标岗位有筛选价值的技能

### 项目素材模板

让用户按下面结构补项目，越具体越好：

```markdown
## 项目名

- 项目背景：这个项目/系统解决什么问题，服务谁
- 你的角色：主导、核心开发、参与、协作方
- 技术/方法：用了什么技术、工具、方法
- 关键动作：你具体做了什么
- 难点与权衡：为什么难，为什么选这个方案
- 结果证据：数字、范围、效率、质量、用户、收入、风险降低
- 面试风险：哪些地方你担心被问穿
```

## 高质量追问

当材料太平时，用这些问题挖事实：

- 这个项目最难的问题是什么
- 如果没有你这项工作，会有什么损失或低效
- 你最终交付的产物是什么：系统、平台、工具、流程、组件、规范、看板还是机制
- 谁使用了你的产物，使用频率或覆盖范围是多少
- 有没有延迟、吞吐、成功率、转化率、人天、发布时长、排障时间等变化
- 当时有哪些备选方案，你为什么没选
- 你个人贡献和团队贡献怎么区分
- 这段经历最可能被面试官质疑哪里

## 提问输出格式

用户要求“你来问我”时，按用途分组，最多先问 8 到 12 个问题：

```markdown
## 我先问这几类信息

### 1. 目标岗位
1. ...

### 2. 最核心项目
2. ...

### 3. 可量化结果
3. ...

### 4. 面试风险
4. ...

回答完这些，我就能先给你搭一版简历骨架。
```

## 素材取舍

- 面向不同岗位，同一项目可以有不同讲法。
- 技术岗突出技术复杂度、架构权衡、稳定性和工程质量。
- 产品/运营岗突出用户、指标、策略、推进和业务结果。
- 管理岗突出目标拆解、组织协同、决策质量和团队产出。
- 不要为了覆盖所有信息而牺牲主线；简历不是项目档案。
