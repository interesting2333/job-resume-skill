# 岗位画像、职级与能力模型

## 目标

把“我要投某岗位”转成可操作的画像：岗位类型、职级预期、核心能力、证据要求和简历叙事重心。

## 岗位画像五要素

```text
岗位名称 -> 服务对象 -> 核心任务 -> 关键能力 -> 证明证据
```

分析岗位时，优先回答：

- 这个岗位真正交付什么产物：代码、系统、策略、分析、增长、流程、团队结果还是客户价值。
- 主要服务谁：用户、业务方、销售、运营、研发团队、管理层、客户还是监管方。
- 成败指标是什么：质量、效率、增长、稳定性、收入、成本、风险、体验还是组织产出。
- 候选人的优势应落在哪一层：执行、独立负责、复杂问题、跨团队影响、业务决策或团队管理。

## 通用职级判断

| 层级 | 简历应证明 | 常见证据 |
| --- | --- | --- |
| 初级 | 能稳定完成明确任务 | 具体模块、工具使用、交付质量、学习速度 |
| 中级 | 能独立负责一个模块或流程 | 需求拆解、方案选择、上线结果、问题闭环 |
| 高级 | 能解决复杂问题并影响多人协作 | 架构权衡、性能/稳定性、跨团队推进、复盘改进 |
| 专家 | 能定义方向或沉淀平台能力 | 标准化、平台化、技术决策、长期影响、复杂系统治理 |
| 管理 | 能通过团队拿结果 | 目标拆解、资源协调、机制建设、人才培养、组织效率 |

## 技术岗叙事

重点证明：

- 技术复杂度：并发、性能、稳定性、一致性、安全、兼容性、可观测性。
- 架构判断：为什么这样设计，有哪些备选方案，怎么控制风险。
- 工程质量：测试、CI/CD、监控、灰度、回滚、文档、规范。
- 影响范围：服务数、接口量、数据量、用户量、团队覆盖范围。

弱信号：

- 只列技术栈，没有项目证据。
- 只写 CRUD，没有场景、约束和结果。
- 把团队成果全部写成个人主导。

## 产品/运营/数据叙事

产品岗：

- 用户问题、需求判断、优先级取舍、指标变化、跨团队推进。

运营岗：

- 用户分层、增长策略、活动/内容/渠道、转化漏斗、复盘机制。

数据分析岗：

- 指标体系、SQL/统计、AB 实验、归因分析、洞察到业务动作的落地。

## 应届生叙事

应届生缺少正式工作结果时，优先证明：

- 项目完整度：从问题到交付，而不是只写课程作业。
- 学习能力：快速掌握新工具并落地到产物。
- 协作能力：分工、沟通、冲突处理、推进结果。
- 职业准备度：实习、竞赛、开源、论文、证书、作品集。

可以参考 NACE 的通用胜任力：沟通、批判性思维、团队协作、职业素养、技术素养、领导力、职业发展。

## 职级风险提示

- 经验年限不能直接等于职级，必须看独立负责范围和影响范围。
- 简历声称“高级/专家/负责人”时，项目必须出现复杂度、决策、结果和边界。
- 如果用户目标职级高于证据强度，应建议降级表达或补充证据。
