# Word 简历解析

## 支持范围

- `.docx`: 默认支持，使用 `scripts/extract_word_text.py` 提取正文、表格、页眉页脚、脚注、尾注和批注文本。
- `.docm`: 按 Open XML 文档尽力提取文本，不执行宏。
- `.doc`: 旧二进制 Word 格式，不能用 zip/XML 直接解析。优先尝试本机可用转换工具；如果不可用，请用户转存为 `.docx` 或 PDF。

## 解析原则

- 先解析原文，再做简历判断。不要根据文件名、用户摘要或格式猜内容。
- 保留文本顺序优先于保留视觉排版。简历审计重点是内容质量、术语、时间线和经历证据。
- 表格内容要提取，因为很多 Word 简历用表格排版。
- 批注、页眉页脚、脚注可能包含重要信息，应合并到解析结果中，并标注来源。
- 如果解析结果明显缺失，例如只有少量乱码或空文本，要说明解析失败并要求用户转存或粘贴文本。

## 推荐命令

```bash
python scripts/extract_word_text.py path/to/resume.docx
```

输出 Markdown 风格文本，供后续审计、改写或面试对抗使用。

## 旧 `.doc` 处理

按环境能力依次尝试：

1. 如果系统有 Microsoft Word 自动化能力，可让用户另存为 `.docx` 后再解析。
2. 如果系统有 LibreOffice，可先转换为 `.docx` 或 `.pdf` 再解析。
3. 如果都不可用，直接请用户导出 `.docx`、PDF，或粘贴简历全文。

不要声称已经完整读取 `.doc`，除非确实获得了可读文本。

## 解析后检查

提取文本后，先快速检查：

- 是否包含姓名、联系方式、教育/工作/项目经历等基本模块。
- 是否出现大面积乱码。
- 时间线是否完整。
- 表格拆出来后是否丢失项目和 bullet 的对应关系。

如果 Word 排版导致顺序混乱，在输出中说明“解析顺序可能受表格排版影响”，并优先基于可识别模块审计。
