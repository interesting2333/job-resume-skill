# 一页简历

## 使用条件

只有在以下情况生成一页版：

- 用户明确要求一页版
- 用户确认需要一页版
- 用户原始任务就是压缩到一页

如果用户只是说“整份优化”，先问：

```text
要不要我顺手再给你压缩成一页版简历？
```

## 目标

一页版不是删字游戏，而是把最能提高面试转化率的信息压到一页内：

- 30 秒内看懂候选人是谁
- 第一屏看到和目标岗位最相关的成果
- 减少背景噪音

## 压缩原则

优先保留：

- 最近 5 到 8 年内经历
- 与 JD 高度相关的项目和技术
- 能体现复杂度、影响力、职级和结果的成果

优先删除或弱化：

- 弱相关早期经历
- 没有结果的职责描述
- 重复技能清单
- 空洞自评
- 低信息量项目

每段经历通常保留 2 到 4 条 bullet，优先级：

1. 最能证明岗位匹配度的成果
2. 最能证明技术/业务复杂度的成果
3. 最能证明 ownership 或跨团队协作的成果
4. 其他支持性信息

## 推荐结构

```markdown
# 姓名 | 目标岗位

## 职业摘要
[1 到 2 行，写方向、年限、最强价值]

## 核心技能
[按目标岗位保留 6 到 12 个关键词]

## 工作经历
### 公司 / 岗位 / 时间
- [高密度成果 bullet]
- [高密度成果 bullet]
- [高密度成果 bullet]

### 公司 / 岗位 / 时间
- [高密度成果 bullet]
- [高密度成果 bullet]

## 项目 / 教育
[只保留最相关内容]
```

## 判断标准

- 第一屏能看出目标岗位
- 最近经历比旧经历更突出
- 至少有 3 条能体现结果的 bullet
- 技能、经历、目标岗位能互相印证
- 即使压缩，也尽量保留每个核心项目的一句话上下文
