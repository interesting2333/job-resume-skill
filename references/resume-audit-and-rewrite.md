# 简历审计与改写

## 30 秒初判

先给一句结论：

- 招聘方是否会继续看
- 最大扣分点是什么
- 最大可放大亮点是什么

这一段要短、准、直接。

## 审计维度

### 职业故事线

检查：

- 路径是否连贯
- 转岗、跳槽、空窗是否需要解释
- 最近经历是否支撑目标岗位
- 是否有外包、驻场、短期经历需要重新叙述

### JD 与关键词

检查：

- 摘要和前半页是否能命中目标岗位
- 技术栈/能力标签是否和项目经历相互印证
- 是否堆了很多和岗位无关的技能

### 项目上下文

每个项目先写一句背景：

```text
[系统定位] + [服务对象] + [解决的业务问题]
```

没有上下文的 bullet 会让面试官无法判断含金量。

### Bullet 质量

弱表达：

- 负责
- 参与
- 协助
- 熟悉
- 了解

强表达：

- 主导
- 设计
- 重构
- 优化
- 推动
- 落地
- 建立
- 交付

优先改成：

```text
为了[目标/问题]，我[动作]，交付了[产物]，带来[结果]。
```

或：

```text
在[约束/挑战]下，评估[方案 A/B]，选择[方案]并通过[补偿措施]控制风险，最终[结果]。
```

## 量化补强

优先找这些数字：

- 性能：延迟、吞吐、成功率、可用性、错误率
- 业务：转化率、GMV、留存、订单量、收入、客诉
- 效率：人天、发布时长、排障时间、交付周期、手工步骤
- 规模：用户数、接口量、数据量、服务数、团队覆盖范围
- 风险：事故次数、恢复时间、重复问题、误操作概率

没有精准数字时，不要编。可以降级为：

- 高频/低频
- 分钟级/小时级/天级
- 单团队/多团队/全公司
- 核心链路/关键系统/基础设施
- 从手工到自动化、从不可观测到可追踪、从分散脚本到统一平台

## 改写规则

- 忠于原文，不凭空扩写。
- 优先改最近经历、最相关项目、摘要和核心技能。
- 删除低价值自评和重复技能。
- 术语、时间、职责、项目规模前后一致。
- 缺少事实时使用占位符：

```text
[项目背景待补：这个系统服务谁、解决什么问题]
[量化指标待补：例如接口延迟从 800ms 降至 200ms]
[个人贡献待补：说明你负责的模块/决策/落地动作]
```

