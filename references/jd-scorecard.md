# JD 匹配评分卡

## 目标

把 JD 拆成可验证的要求，并判断当前简历是否有证据支持。评分卡用于 JD 定制、简历审计、投递策略和面试风险预警。

## 拆解结构

```text
JD 要求 -> 能力维度 -> 简历证据 -> 匹配强度 -> 改写动作 -> 面试风险
```

## 评分维度

| 维度 | 看什么 | 强证据示例 |
| --- | --- | --- |
| 硬技能 | 语言、框架、工具、平台、方法 | 项目中真实使用并交付结果 |
| 业务经验 | 行业、业务流程、用户场景 | 能说清业务问题和指标变化 |
| 复杂度 | 数据量、并发、稳定性、跨系统协作 | 有约束、权衡、方案和结果 |
| 产出影响 | 成本、效率、收入、质量、风险 | 有量化或可验证范围 |
| Ownership | 是否独立负责和闭环 | 个人动作、决策边界、上线/复盘 |
| 协作影响 | 跨团队、推动、沟通、对齐 | 推进路径、冲突处理、机制沉淀 |
| 成长潜力 | 学习速度、迁移能力、主动性 | 新领域快速落地、复盘迭代 |

## 匹配等级

| 等级 | 判断标准 | 处理 |
| --- | --- | --- |
| 强匹配 | JD 要求在简历中有项目证据和结果 | 前置、展开、量化 |
| 中匹配 | 有相关经历，但证据不够清楚 | 改写上下文，补动作和产物 |
| 弱匹配 | 只有技能词或相邻经验 | 保留为辅助，避免夸大 |
| 缺口 | 没有证据 | 标为待补充或准备解释 |
| 风险 | 简历写了但经不起追问 | 降级表达、补证据或删除 |

## 证据链要求

每个关键能力最好能形成证据链：

```text
能力关键词 -> 项目场景 -> 个人动作 -> 交付产物 -> 结果/影响 -> 可防守证据
```

示例：

```text
服务治理 -> 多服务调用链路不稳定 -> 设计超时/重试/熔断策略 -> 统一治理组件 -> 故障恢复时间降低[待补] -> 监控看板/事故复盘/上线记录
```

## 输出格式

```markdown
## JD 匹配评分卡

| JD 要求 | 当前证据 | 匹配等级 | 改写动作 | 面试风险 |
| --- | --- | --- | --- | --- |

## 应前置的内容

## 应补证据的内容

## 不建议硬凑的内容
```

## 不完整 JD

如果用户只给岗位名：

- 先按通用岗位画像判断，但必须说明是“基于岗位名的推断”。
- 优先问 1 到 3 个澄清问题：目标行业、职级、技术/业务重心、公司类型。
- 不输出过度具体的关键词堆砌。
