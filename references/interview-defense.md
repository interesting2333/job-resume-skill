# 面试对抗与讲稿

## 目标

让简历里的每个亮点都经得起面试官追问。不要只生成题库，要帮助用户形成能说出口、能防守、能补证据的回答。

## 简历追问生成

从简历中抽取：

- 最大亮点：面试官会深挖真实性和复杂度
- 最大风险：面试官会验证是否夸大
- JD 缺口：面试官会问怎么弥补
- 时间线异常：HR 会问动机和稳定性

每个问题输出：

```markdown
## Q1. [问题]

- 考察点：
- 为什么会问：
- 好答法：
- 差答法：
- 可能追问：
- 需要补齐的证据：
```

## 项目讲稿

每个核心项目生成 60 到 90 秒口述版：

```text
开场定位 -> 背景与问题 -> 我做了什么 -> 关键权衡 -> 结果 -> 和目标岗位的连接
```

要求：

- 口语化，可直接说出口。
- 先讲结论，再讲细节。
- 不把讲稿写成完美背诵稿，要保留自然表达。
- 缺事实时标注 `[待补充]`。

## 好答案 vs 差答案

差答案要像真实候选人会犯的错：

- 空泛
- 全是“我们”，没有个人贡献
- 没有结果
- 没有技术/业务权衡
- 一上来背概念，不结合项目

好答案要体现：

- 结论先行
- 背景清楚
- 个人动作具体
- 结果可证明
- 能承认边界和复盘

## 技术/项目题回答框架

```text
一句话结论
-> 项目背景或技术问题
-> 我的方案和关键动作
-> 为什么这样选，取舍是什么
-> 结果和数据
-> 如果重做会怎么优化
```

## 行为面试 STAR/BEI

按以下维度追问用户回答：

- S/T 不清楚：当时背景、目标、约束是什么
- A 不具体：你个人做了什么，是主导还是参与
- R 没数据：结果怎么证明
- 全是“我们”：你的贡献是什么
- 过于完美：遗憾、复盘和改进是什么

## HR 面防守

常见主题：

- 求职动机
- 离职原因
- 空窗期
- 频繁跳槽
- 转行
- 薪资预期
- offer 选择
- 职业规划

回答原则：

- 真诚，但不输出情绪化抱怨。
- 承认现实动机，但补上职业逻辑。
- 对高风险问题给“可说版本”，避免暴露无关细节。
- 不贬低前公司、前同事或过往选择。

## 薪资谈判

如果用户要求谈薪，先收集：

- 当前薪资结构
- 目标涨幅或期望区间
- 城市、职级、岗位范围
- 是否已有 offer
- 对方报价和福利结构

没有数字时，只给结构和话术，不臆造市场价。

输出：

```markdown
## 谈判局面

## 建议策略

## 可直接说的话

## 不建议说的话

## 收口边界
```

## 互动模拟

用户要求“模拟面试”时，优先一次问一道题。用户回答后，再做：

1. 追问
2. 点评
3. 改写成更好的回答
4. 标记下一轮风险

如果用户只要题库，再输出 8 到 10 道题，每题包含考察点和追问方向。
